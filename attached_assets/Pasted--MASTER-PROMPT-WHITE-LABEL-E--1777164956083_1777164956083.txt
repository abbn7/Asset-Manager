## 🎯 PROJECT OVERVIEW

Build a production-ready, white-label e-commerce store template
inspired by top Shopify stores and premium clothing/fashion brands
(e.g. Zara, ASOS, H&M online experience).

The store must be:

- Completely EMPTY of real product data (white-label / data-agnostic)
- Visually stunning and premium — better than existing Shopify themes
- Fully functional with a powerful admin dashboard
- Ready to be sold to any brand or retailer as a plug-and-play solution
- Deployable on Vercel in under 10 minutes with zero friction

### RLS Policies (apply to ALL tables):

- users: Users can only read/update their own row. Admins can read all.
- products/collections: Public SELECT when status=‘active’. Admin full access.
- orders: Users SELECT own orders. Admins full access.
- order_items: Same as orders.
- reviews: Public SELECT when status=‘approved’. Users INSERT own. Admin full access.
- wishlists: Users full access to own rows only.
- discount_codes: Admin full access. Auth users can read active codes.
- blog_posts: Public SELECT when status=‘published’. Admin full access.
- store_settings: Public SELECT. Admin UPDATE only.

Helper function for Clerk JWT (run in Supabase SQL Editor):

CREATE OR REPLACE FUNCTION requesting_user_id()
RETURNS TEXT AS $$
SELECT NULLIF(
current_setting(‘request.jwt.claims’, true)::json->>‘sub’, ‘’
)::text;
$$ LANGUAGE SQL STABLE;

## 🔗 API ROUTES SPECIFICATION

All API routes in /src/app/api/
All routes must return: { data, error, meta? }
All routes use Zod for request validation.
All routes return proper HTTP status codes.

### Public Routes (no auth required):

GET  /api/products                → list active products (pagination, filters, sort)
GET  /api/products/[id]           → single product by id or slug
GET  /api/collections             → list all collections
GET  /api/collections/[id]        → single collection with products
GET  /api/search?q=               → full-text search products + collections
GET  /api/reviews/[productId]     → approved reviews for a product
GET  /api/blog                    → published blog posts
GET  /api/blog/[slug]             → single blog post
POST /api/discounts/validate      → validate coupon code
POST /api/checkout                → create Stripe payment intent

### Authenticated Customer Routes:

GET    /api/orders                → my orders
GET    /api/orders/[id]           → my order detail
POST   /api/reviews               → submit review
GET    /api/wishlist              → my wishlist
POST   /api/wishlist              → add to wishlist
DELETE /api/wishlist/[id]         → remove from wishlist

### Admin-Only Routes:

POST   /api/products              → create product
PUT    /api/products/[id]         → update product
DELETE /api/products/[id]         → delete product
POST   /api/collections           → create collection
PUT    /api/collections/[id]      → update collection
DELETE /api/collections/[id]      → delete collection
GET    /api/orders?admin=true     → all orders
PUT    /api/orders/[id]           → update order status
GET    /api/customers             → list all users
POST   /api/discounts             → create discount code
PUT    /api/discounts/[id]        → update discount
DELETE /api/discounts/[id]        → delete discount
PUT    /api/reviews/[id]/status   → approve/reject review
POST   /api/upload                → get Cloudinary signed upload URL
GET    /api/analytics/overview    → revenue, orders, customers summary

### Webhooks:

POST /api/webhooks/clerk          → sync user to Supabase on register
POST /api/webhooks/stripe         → handle payment confirmation, refunds

## 🚀 DEPLOYMENT GUIDE (Vercel — Step by Step)

### Prerequisites:

- Node.js 20+ installed
- Git installed
- GitHub account
- Accounts created on: Vercel, Supabase, Clerk, Cloudinary, Stripe, Resend

### Step 1 — Supabase Setup:

1. Go to supabase.com → New Project → choose region
1. Wait for project to initialize (~2 minutes)
1. Go to SQL Editor → run the schema migrations (in /drizzle/migrations/)
1. Go to Authentication → Providers → add Clerk as Third-Party Auth
1. Copy Project URL and anon key from Settings → API

### Step 2 — Clerk Setup:

1. Go to clerk.com → Create Application
1. Enable Email/Password + Google + Apple
1. Go to API Keys → copy publishable key and secret key
1. Go to Webhooks → Add Endpoint → URL: https://your-domain.vercel.app/api/webhooks/clerk
1. Subscribe to: user.created, user.updated, user.deleted
1. Copy the webhook signing secret
1. To set yourself as admin: Users → select your user → Metadata → add {“role”: “admin”}

### Step 3 — Cloudinary Setup:

1. Go to cloudinary.com → Dashboard
1. Copy Cloud Name, API Key, API Secret from the top
1. Settings → Upload → Add upload preset named “ecommerce_products” (unsigned)

### Step 4 — Stripe Setup:

1. Go to stripe.com → Developers → API Keys
1. Copy publishable key and secret key (use test mode keys)
1. Webhooks → Add endpoint → https://your-domain.vercel.app/api/webhooks/stripe
1. Events: payment_intent.succeeded, payment_intent.payment_failed, charge.refunded

### Step 5 — Resend Setup:

1. Go to resend.com → API Keys → Create Key → copy it
1. Domains → Add your domain and verify (or use onboarding@resend.dev for testing)

### Step 6 — GitHub Push:

git init
git add .
git commit -m “chore: initial store template”
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git push -u origin main

### Step 7 — Deploy to Vercel:

1. Go to vercel.com → New Project → Import from GitHub
1. Select your repository
1. Framework Preset: Next.js (auto-detected)
1. Environment Variables: paste ALL variables from .env.example with real values
1. Click Deploy
1. Wait ~2 minutes for build
1. Visit your Vercel URL → store is live ✅

### Step 8 — Post-Deployment:

1. Update Clerk webhook URL to your Vercel URL
1. Update Stripe webhook URL to your Vercel URL
1. Set NEXT_PUBLIC_APP_URL to your Vercel URL in Vercel dashboard
1. Trigger a Vercel redeploy (Deployments → Redeploy)

### Ongoing Deployments:

Every git push to main automatically redeploys on Vercel.
No manual steps needed after initial setup.
